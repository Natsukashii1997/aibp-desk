AI 是什么

定义 · 家族 · 怎么炼成 · 为什么会出错 · 一条主线
从这一章起，把 AI 想成一位新来的实习生。全课只用这一个比喻。

一句话定义

AI 是能根据输入，自己「推断」出结果的机器。

普通软件

每一步都由人写死

AI

做法是从数据里学出来的

权威定义（大意）
AI 系统是一种基于机器的系统，根据收到的输入推断如何生成输出——预测、内容、建议或决策；不同系统的自主程度不同。
OECD《更新后的 AI 系统定义说明》（2024）

AI 家族：几个容易混的词

按「做什么」再分两类

判别式 AI

做判断、做选择：人脸识别、垃圾邮件过滤、短视频推荐

生成式 AI

生成新内容：写文章、画图、作曲、写代码

日常说的「AI」，现在多指
大模型驱动的生成式 AI——本课只讲这一类

大模型是怎么炼成的：三步

第一步 · 预训练

读海量文本，反复练习
预测下一个 Token

语法、常识、推理套路被压缩进参数

实习生：先博览群书

第二步 · 后训练

看示范、被打分，
学会听懂指令

按格式回答、拒绝有害请求；推理模型还练「先想再答」

实习生：岗前培训

第三步 · 使用（推理）

一个 Token 一个 Token
往下生成

带有随机性：同一问题问两次，答案不完全一样

实习生：上岗答题

「大模型就是猜下一个词」——只说对了一半：生成方式是逐个预测，但它已能遵循复杂指令、分步解题。

为什么它像「懂」，又会出错

没有内置的事实核对

生成的是「最可能的回答」，不保证是「正确的回答」

被训练得爱猜

训练和评测往往奖励「猜一个答案」，不奖励「承认不知道」——幻觉的重要成因

知识有截止日期

截止之后发生的事它不知道，除非联网搜索

流畅 ≠ 正确

第一层：模型本身 必须会

概念大白话实习生比喻常见误区
大模型 / LLM从海量文本学出来、能理解和生成语言的模型读书多，但没在你这儿干过以为它在「查数据库」
模型 vs 产品模型是能力；产品是装着模型的软件，常带搜索、文件、记忆实习生本人 vs 加上他的工位和电脑把 ChatGPT（产品）和 GPT（模型）混为一谈
Token处理文字的基本单位；也是 API 计费单位按字数算的工作量一个 Token 就是一个汉字（各模型切法不同）
上下文窗口一次能「看到」的最大内容量，含你的输入和它的输出工作台的大小，放不下就看不见「聊得越久它越懂我」
幻觉生成看似合理、实际错误的内容不懂装懂、自信地答错回答越流畅越可信

第一层：模型本身 知道就行

概念大白话实习生比喻常见误区
参数模型内部可调的数值，「千亿参数」说的就是它脑容量参数越多就一定越好用
训练 vs 推理训练是「学」，推理是「用」；你平时用 AI 都是推理上学 vs 上班以为跟它聊天就是在训练它
多模态能处理文字以外的图片、语音、视频还能看图、听录音—
推理模型回答前先内部思考，适合数学、逻辑、规划类难题做题前先打草稿简单问题也用它，又慢又贵
开源 / 闭源开源（多是「开放权重」）能下载自己部署；闭源只能通过官方产品或接口用能不能把实习生请到自己家干活开源等于免费

第二层：提示词与上下文 必须会

提示词 Prompt

你给 AI 的指令

实习生比喻：你给实习生的工作交代

误区：有万能模板、写得越花哨越好

上下文 Context

模型此刻能看到的全部信息

系统设定、对话历史、你给的资料、工具返回的结果
实习生比喻：交代任务时摊在桌上的所有材料

误区：只说「帮我写周报」，不给素材

AI 答非所问，多半是上下文不够，
而不是提示词不够花哨。
这就是开场演示里，第二次好得多的一半原因。

让 AI 用上「它本来不知道的资料」：五种方式

方式怎么做什么时候用局限
直接给贴进对话或上传文件一次性任务、资料不多受上下文窗口限制，聊完就没了
联网搜索让 AI 实时搜网页再回答需要最新信息来源质量参差，要点开核对
知识库 / RAG先从资料库检索相关片段，再交给模型作依据资料多、要反复查检索错，答案照样错；能减少幻觉，不能消除
记忆 Memory产品把你的偏好和关键信息存下来，下次自动带上长期用同一个助手不是所有产品都有；记错了要手动改
微调用一批示例数据再训练模型企业、开发者的专门需求成本高，不适合用来「教它新知识」

第三层：工作流 vs Agent 必须会

工作流 Workflow

由人预先设定好步骤，AI 按顺序执行

实习生：照着 SOP 一步步做

✔ 可预测、好管理

智能体 Agent

由模型自己决定下一步做什么、用什么工具，直到完成目标

实习生：交代目标后，自己想办法办成

✔ 更灵活　✘ 更难预测、成本更高

口诀：步骤固定 → 工作流；步骤要看情况定 → Agent。
能用简单方案，就不用复杂方案。

热词速查（上）：听到这些词，知道它为什么重要

AGI 通用人工智能

在大多数任务上达到或超过人类水平的 AI。没有公认标准，听到「AGI 已来」要打个问号

提示词工程

怎么写指令让模型表现更好。模型越强，越看重「交代清楚」，而不是背技巧

上下文工程

设计「让模型看到什么」。长任务成败往往取决于上下文管得好不好

RAG 检索增强生成

先检索资料，再据此回答。能用上私有、最新的资料并标出处；能减少幻觉，不能消除

深度研究

AI 自己搜大量网页，写出带引用的报告。把几小时调研压到几十分钟；仍要核对引用

记忆 Memory

产品跨对话记住你的偏好和事实。越用越懂你；也要定期检查它记了什么

热词速查（下）：行动、质量与安全

Agent 循环　想 → 做 → 看结果 → 再想；能做长任务、能自我纠错的根本原因
MCP　AI 连接外部工具和数据的开放协议；工具接一次，各家 AI 都能用
Skill　带说明、脚本和资源的能力文件夹；把「怎么做一件事」沉淀下来、团队复用
Computer Use / 浏览器 Agent　像人一样看屏幕、点鼠标；没有接口的软件也能操作，目前还慢、会出错
Vibe Coding　用自然语言让 AI 写代码、自己不逐行看；能做出小工具，上线前要有人懂得检查
人在回路　关键步骤由人确认后才继续；「放手」和「放心」之间的平衡点
闭环 / 反馈回路　执行结果回传，用来检查和改进；没有回流，就发现不了错误
提示词注入　把恶意指令藏进网页、邮件、文件；Agent 时代最主要的安全风险之一

交代任务：六件事说清楚

给新来的实习生交代任务要说什么，给 AI 就说什么。
要素要回答的问题周报例子
任务要做什么把本周工作记录整理成周报
背景给谁看、为什么给部门负责人看，用于周会
材料依据什么附上本周工作记录
格式交成什么样，最好附范例分「完成事项 / 关键数据 / 问题与风险 / 下周计划」四段，每段不超过 5 条
约束不能怎样只用我给的材料；没提供的数字写「待补充」，不要自己编
验收怎样算合格每条都能在原始记录里找到依据
揭晓：开场第二次好得多，就好在把这六件事说清楚了。

交代任务：四个好习惯

1

背景给足

答非所问时先补材料，不要先换说法

2

一次只聊一件事

换话题就开新对话，避免旧内容干扰

3

让它先问你

任务复杂时说：「开始前先问我缺什么信息」

4

迭代

第一版不满意，具体指出哪里不对，让它改

「你是一位资深 XX」可以用，但不是关键：材料和要求比角色重要得多。
「没提供的写待补充」这一句最值钱，能大幅减少编造。

检查结果：核验四步

1

事实

关键事实回到原始来源核对

2

数字

数字和日期单独重算、重查

3

引用

链接和出处逐条点开，确认存在且确实支持结论

4

逻辑

因果是否成立，结论有没有越出材料范围

养成习惯：错误记录

记下错误类型、在什么情况下出错、怎么发现的。一个月后，你就知道 AI 在你的工作里哪里靠得住、哪里靠不住。

第七章

进阶：数字分身

四个说法 · 工具和分身的区别 · 七层架构 · Hermes 实例 · 成长路径
定位：看懂 AI 正在往哪里走。只要求理解，不要求搭建。

先分清四个说法

说法是什么例子
AI 工具你发起一次任务，它给出结果，用完就结束打开对话助手问一个问题
Agent围绕一个目标，自己选步骤、调工具让编程 Agent 修一个 Bug
数字分身（岗位分身）围绕一个岗位长期运行：固定角色、知识与记忆、工具、触发方式和结果汇报每天整理行业资讯并推送；在群里答复常见问题
数字人有虚拟形象和声音的 AI，重点在「外表」虚拟主播、数字人客服
数字分身 ≠ 数字人：分身讲「替岗位干活」，数字人讲「长得像人」。

工具和分身的区别

AI 工具岗位数字分身
存在方式你打开它，它才工作长期运行，出现在消息平台里
职责不承担岗位职责承担岗位的一部分沟通、值班、交付
积累技巧主要留在个人身上角色说明、知识、Skill 沉淀为可交接的资产
人不在时停止继续按规则运行，异常时找人
判断标准：能不能在人不在场时，独立、可靠地承担一个岗位的一部分工作。
参考混沌《数字分身》课程（刘雨飏）的对比并加以修正

七层架构：一条消息要走完的路

层名称做什么对应第三章概念
L1接入层消息从哪里来：聊天软件、邮件、网页输入
L2沟通层理解意图，和人对话模型、提示词、上下文
L3调度层拆解任务、排定顺序、跟踪状态工作流、Agent
L4执行层实际干活，例如调用编程 Agent工具调用
L5能力层听、看、存等专项能力Skill、MCP、多模态
L6记忆层角色设定、长期记忆、项目知识记忆、知识库
L7资产层文件、数据、代码仓库资料来源
治理线
贯穿所有层：
身份与权限
人工确认点
运行留痕
异常处理
结果回读
左：下行派活——理解需求 → 逐层分解 → 调用能力 → 触达资产右：上行回流——执行结果 → 状态反馈 → 沉淀知识
这是一门课程提出的教学框架，不是行业标准。只派活不回流，就形不成闭环。
